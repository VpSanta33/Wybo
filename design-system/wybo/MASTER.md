# Wybo · 望月小铺设计规范

## 方向与依据

用户明确指定 https://gptibo.com/ 为视觉参考。采用其极简的直接选购结构：顶部胶囊分类、左侧单一产品视觉、右侧白色下单卡片、底部简洁链接。月兔以原创蓝色 SVG 形象与黑白品牌标志融入。

使用已安装的 UI UX Pro Max 检索 `minimal digital storefront checkout`，匹配 Minimalism & Swiss Style。采用其留白、清晰层级、短暂悬停反馈及可访问表单建议；布局以用户的参考站为准，不采用检索返回的通用 Hero + Features 模板。

## 视觉

- 背景 `#f7f8fa`，表面白色，正文 `#242529`。
- 主按钮炭黑 `#292b30`；选择、焦点与月兔使用蓝色，选中面 `#f7f9ff`。
- 字体使用系统 sans-serif 与中文系统字体，无外部字体请求。
- 分类为胶囊切换；商品方案 12px 圆角，下单卡片 23–27px 圆角。
- 桌面容器最大 1200px，展示区与 430px 下单卡片组成双栏；900px 以下切换纵向布局。
- 桌面商品主图最大宽度 350px，左侧展示区顶部对齐，不随下单卡片增高而下沉；平板和手机分别使用 260px / 225px，并限制在容器宽度内。
- 下单卡片使用两列套餐选择，保留商品缩略图与价格；标题省略重复的品牌名，完整名称用于无障碍标签和订单核对。邮箱与数量并排，370px 以下改为分行。支付与发货信息合并为一行，金额与下单按钮并排，商品说明与标签收进折叠区。
- 已识别产品使用本地品牌 SVG 作为主图、导航图标和套餐缩略图，月兔缩小为品牌点缀。自定义商品封面优先；图片失败时回退到品牌图。品牌素材来自 MIT 许可的 LobeHub Icons，来源记录在 `frontend/public/brands/`。

## 交互

- 分类使用 tablist / tab / tabpanel，支持方向键、Home、End 与可见焦点。
- 分类超出可用宽度时显示左右浏览按钮，保留触屏横向滑动；按钮在首尾禁用，选中分类及窗口尺寸变化时自动保持选项可见，仅滚动分类栏。分类文字不压缩到难以阅读，触控高度至少 44px。七个以上分类使用数字进度，避免展示区圆点横向溢出。
- 前台按接口分页完整加载商品，保留代理价格与中断取消，超过 100 件的商品不会被截断。以 19 个分类、146 件商品验证全部分类与每类 8 个套餐，并检查 320 / 375 / 1024 / 1280px 页面无横向溢出。
- 商品套餐使用原生 radio，数量有库存上限，售罄不可提交。ChatGPT Plus / Pro 5x / 20x / 50x 使用不同商品 ID。
- 售价为 0 显示「待定价」，可切换查看，前端和后端均禁止创建订单；售价和库存由后台管理。
- 邮箱持续标签、浏览器校验与行内错误；购买条款需明确勾选。
- 下单先核对商品、数量、邮箱、金额，再提交；请求期间锁定表单与重复提交。
- 使用原生 dialog 约束焦点、支持 Escape，并恢复触发元素焦点；提交期间保留弹窗。
- 正式支付读取后台已启用的 Stripe / 易支付 / DujiaoPay / BEpusdt 渠道。演示模式有明确标记，不伪造付款成功或真实卡密。
- 手机使用纵向排列，无固定悬浮遮挡；支持 prefers-reduced-motion。

## 页面与结构

- `Storefront.tsx`：选购与下单。
- `Illustrations.tsx`：月兔品牌与产品展示 SVG。
- `components.tsx`：弹窗、错误提示、订单摘要、支付动作。
- `App.tsx`：路由、查询、指南、帮助及隐私和条款。
- 真实 API 数据与演示订单逻辑继续使用 `api.ts`。

## 本轮验证

- `npm run build` 与 `go test ./...` 通过。
- 后端测试覆盖：未定价商品即便有卡密库存也不能下单；后台改价后新订单使用更新后的金额。
- 本地 API 已确认三个 Pro 商品存在、待定价订单被拒绝，未创建订单记录。
- 紧凑下单布局通过 320 / 375 / 1024 / 1440px 浏览器检查，无横向溢出；已验证待定价禁购、分类切换、数量合计与订单核对弹窗（2 份合计 ¥396.00），未提交订单。桌面默认下单卡片约 663px 高，1024×720 视口内可见下单按钮。
