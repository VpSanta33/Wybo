# 支付渠道配置指南

适用于当前 Wybo 的 Stripe、易支付、DujiaoPay 和 BEpusdt 实现。以 `https://shop.example.com` 举例，请替换成自己的正式域名。部署脚本不申请商户账号、不填入商户密钥，也不会自动发起扣款。

## 先确认公共地址

原生部署脚本会为全新数据库初始化以下值；已有配置不覆盖。站点域名在后台「站点设置 → 下单防护 → 网站正式地址」管理（与上线检查共用），两个付款地址在「站点设置 → 支付地址」检查：

| 后台字段 | 所在页面 | 示例 |
| --- | --- | --- |
| 站点域名 | 站点设置 → 下单防护 | `https://shop.example.com` |
| 公网回调基础地址 | 站点设置 → 支付地址 | `https://shop.example.com/api/v1/pay/notify` |
| 付款返回地址 | 站点设置 → 支付地址 | `https://shop.example.com/orders` |

回调基础地址不带渠道代码，不带尾部 `/`。四个完整回调地址是：

| 渠道 | 配置给支付服务商的完整地址 |
| --- | --- |
| Stripe | `https://shop.example.com/api/v1/pay/notify/stripe` |
| 易支付 | `https://shop.example.com/api/v1/pay/notify/epay` |
| DujiaoPay | `https://shop.example.com/api/v1/pay/notify/dujiaopay` |
| BEpusdt | `https://shop.example.com/api/v1/pay/notify/bepusdt` |

支付服务商必须能从公网访问 HTTPS 回调地址。不要给 `/api/v1/pay/notify/` 添加登录、Basic Auth、验证码、页面缓存或强制浏览器挑战。域名迁移后需要同时更新站点地址、回调基础地址、付款返回地址，以及 Stripe / DujiaoPay 商户后台登记的 Webhook。

Cloudflare Turnstile 仅保护新建订单，不验证支付回调；配置方法见 [站点设置与人机验证](站点设置与人机验证.md)。

后台「支付渠道」进入对应渠道的配置，保存密钥并启用。密钥加密保存在数据库，读取时返回遮罩；保留遮罩表示沿用已有密钥。只启用实际配置、开通成功的渠道。

前台使用可见的支付方式单选卡片，显示方式名称、渠道 Logo 与说明。易支付按后台 `type` 显示支付宝（默认）、微信支付或 QQ 钱包；Stripe 手动模式只列出配置的方式，自动模式提示以收银台实际可用方式为准；DujiaoPay 和 BEpusdt 默认显示「USDT支付」，提示使用 USDT 钱包并核对收银台网络、金额。即使只启用一个渠道，也会展示方式说明。接口只返回这些展示信息，不返回商户密钥或网关配置。

## 对外名称与 Logo

在「支付渠道 → 配置渠道 → 前台展示」设置顾客看到的名称，例如「支付宝」「微信支付」「USDT支付（TRC20）」。留空时系统按渠道实际支付类型自动命名；名称最多 60 个字。后台仍保留 Stripe、易支付、DujiaoPay、BEpusdt 的服务商名称，方便核对接口配置。

点击「上传 Logo」选择 PNG、JPG 或 GIF，最大 2 MB、最大 4096 × 4096，建议使用正方形透明底图片。上传后先预览，再点击「保存配置」生效。上传只保存图片，不会自动启用渠道或覆盖商户密钥。可点击「恢复默认 Logo」后保存；前台图片加载失败时也会使用默认图标。图片保存在服务器 uploads 目录，沿用部署脚本的持久化和备份机制。

对外名称只影响展示，不改变真实收款方式、币种、链或回调协议。DujiaoPay / BEpusdt 显示为「USDT支付」时，请在服务商后台及本项目的 chain / token_id / trade_type 中配置实际支持的 USDT 网络，避免开启其他币种后产生歧义。两条渠道均启用时，建议通过名称注明实际网络或线路，方便顾客区分。

## Stripe

本项目采用 **Stripe Checkout 一次性付款**，支持银行卡、支付宝（`alipay`）和微信支付（`wechat_pay`）。商品订单金额单位为人民币分，支付币种固定 `cny`。后台的「订单收款币种」不代表 Stripe 账户的最终银行结算币种；项目不会自动把人民币价格换算成美元。

### 1. 获取 API 密钥

在 [Stripe Dashboard](https://dashboard.stripe.com/) 的 API keys 页面取得 Secret Key。

- 先使用测试环境 / Sandbox 的 `sk_test_…`。
- 真实收款时使用正式模式的 `sk_live_…`。
- 这里不需要填写 `pk_…` Publishable Key，前台不会接触 Secret Key。

### 2. 注册 Webhook

在 Stripe Workbench / Webhooks 添加事件目的地，填写：

```text
https://shop.example.com/api/v1/pay/notify/stripe
```

订阅这两个事件：

```text
checkout.session.completed
checkout.session.async_payment_succeeded
```

复制**这个目的地**的 Signing Secret，形如 `whsec_…`。测试与正式模式的目的地和签名密钥彼此独立；Stripe CLI 转发时生成的签名密钥也不等同于生产目的地密钥。

### 3. 填写 Wybo 后台

| 字段 | 填写内容 |
| --- | --- |
| Secret Key | 当前模式对应的 `sk_test_…` / `sk_live_…` |
| Webhook 签名密钥 | 相同模式、相同目的地的 `whsec_…` |
| 订单收款币种 | `cny` |
| Checkout 支付方式 | 默认「跟随 Stripe 后台（推荐）」；也可选「手动选择支付方式」并勾选银行卡 / 支付宝 / 微信支付 |

保存后启用。确认自己的 Stripe 账户及已开通支付方式支持 CNY Checkout；不支持时需要另行实现币种换算方案，不能只把字段改成 `usd`。

### 开通支付宝与微信支付

1. 打开 [Stripe 后台 → 支付方式](https://dashboard.stripe.com/settings/payment_methods)，选择对应的正式 / 测试环境。
2. 找到 **Alipay（支付宝）** 和 **WeChat Pay（微信支付）**，按账户提示申请或启用，并完成 Stripe 要求的商户资料。
3. Wybo 保持「跟随 Stripe 后台」时，不固定 `payment_method_types`，Stripe 会根据账户地区、订单币种、顾客及设备条件动态展示已开通且可用的方式。
4. 需要限定方式时，在 Wybo 选择手动模式，至少勾选一种。手动勾选不等于已在 Stripe 开通；不具备资格的方式可能导致创建收银台失败。
5. 微信支付创建 Checkout Session 时要求 `payment_method_options[wechat_pay][client]=web`；系统在自动模式或勾选微信时已自动传入。支付宝不需要微信客户端参数。
6. 顾客在 **Stripe 托管收银台** 选择支付宝 / 微信完成付款，仍使用相同的 `/stripe` Webhook 验签、入账和发卡，不需另填国内直连商户 PID、支付宝私钥或微信 API v3 密钥。

是否能开通以你的 Stripe 账户后台为准。官方文档的支持地区及币种可能更新；当前采用一次性付款，不通过这两种方式创建会员自动续费订阅。Stripe 托管收银台可能只展示对当前交易符合条件的方式。

官方参考：[Alipay Checkout 接入](https://docs.stripe.com/payments/alipay/accept-a-payment?payment-ui=checkout) · [WeChat Pay Checkout 接入](https://docs.stripe.com/payments/wechat-pay/accept-a-payment?payment-ui=checkout)

### 4. 测试与切换正式环境

在商城创建真实的测试模式订单，进入 Checkout，按 [Stripe 测试指南](https://docs.stripe.com/testing) 使用测试卡完成支付。测试订单也会在本店发出库存，因此使用专门的测试商品和测试卡密。

支付宝 / 微信需分别按对应官方测试流程验收；例如微信测试收银台会显示二维码，扫码后进入 Stripe 测试授权页面，不是向真实钱包扣款。应分别验证付款跳转、成功回调和只发货一次。

确认 Stripe 事件投递成功，Wybo 订单只发货一次。切换正式模式时，同时更换 Secret Key 和正式 Webhook Secret，再做一次你确认金额的小额验收。单独点击 Stripe 的模拟事件不能证明真实商城订单已正确关联。

### 最低收款金额与 `amount_too_small`

`currency=cny`、`unit_amount=100` 代表人民币 ¥1.00。Stripe 的最低收款金额取决于账户的银行结算币种；人民币订单需要换汇时，换汇后的金额也必须满足相应门槛。官方当前列出的港币门槛为 HK$4.00、美元为 US$0.50，不能把错误信息中的 `400 cents` 一律理解为人民币 ¥4 或美元 US$4。

例如 `¥1.00 converts to approximately $1.18`、最低 `400 cents` 的错误与港币结算相符，应在 Stripe 后台核实实际结算币种。可先将测试商品设为人民币 ¥10，再创建新订单验证；这只是测试建议，最终限制以 Stripe 账户和接口返回为准。后台改价不会修改已创建订单的金额，不要继续使用原来的 ¥1 订单，也不要仅将币种改为 `usd` 或直接放大支付金额。

系统收到 Checkout 的明确 `amount_too_small` 拒绝后，会向顾客提示「订单金额低于 Stripe 最低收款限制」，支付申请记录为失败并保留原因。再次点击同一订单不会重复请求；可以选择其他渠道，或在调整商品数量 / 测试商品价格后创建新订单。其他网络超时、无法解析的响应及服务端错误仍保留待确认状态，避免误判已创建的收银台。

最低金额不使用固定人民币阈值，因为结算币种、汇率和支付方式会影响限制。参考：[Stripe 最低与最高收款金额](https://docs.stripe.com/currencies#minimum-and-maximum-charge-amounts)、[amount_too_small 错误说明](https://docs.stripe.com/error-codes/amount-too-small)。

### 支付宝扫码后提示「买家认证不通过」

能进入 Stripe Checkout，但支付宝扫码后提示「买家认证不通过，无法继续交易」，属于付款认证阶段的失败，和创建收银台时的 `amount_too_small` 不同。仅凭这句中文不能确定是买家账户限制、渠道风控、支付资格还是商户侧原因；需要查看本次付款记录，不能通过跳过验签、强行标记已付款或修改金额解决。

1. 在 Wybo「支付对账 → 支付申请」找到这笔 Stripe 订单，点击「核对渠道」。系统会根据保存的 Checkout Session 读取 PaymentIntent；有错误码时，结果会显示 Stripe 状态、`last_payment_error.code` 和 `decline_code`，不会把买家信息或 `client_secret` 写入记录。
2. 在 Stripe 正式环境的「支付」中找到相同订单号或 PaymentIntent（`pi_...`），查看失败详情和事件。创建 Checkout 的成功请求日志只说明收银台已创建，不能说明后续扫码认证成功；必要时提供 PaymentIntent ID 给 Stripe 支持查询底层支付宝拒绝原因。
3. 按支付宝 App 的实际提示核对实名、账户和当前付款方式的可用状态，并在 Stripe 后台检查 Alipay 支付能力是否仍为可用。若仅某个买家失败，优先由该买家联系支付宝核实；若多个买家均失败，应让 Stripe 核查商户 Alipay 能力及此次拒绝记录，避免在未知原因下反复尝试付款。

支付宝付款需要买家在支付宝完成授权，商城没有额外的「买家认证开关」。`wechat_pay.client=web` 只用于微信支付，修改它不能修复支付宝认证拒绝。若 Stripe 未返回底层错误码，后台仍可能只显示待付款状态，需要以钱包提示和 Stripe 支持的查询结果定位。

参考：[Stripe 支付宝付款流程](https://docs.stripe.com/payments/alipay/accept-a-payment?payment-ui=checkout)、[PaymentIntent 对象与 last_payment_error](https://docs.stripe.com/api/payment_intents/object)。

参考：[Checkout 文档](https://docs.stripe.com/payments/checkout) · [Webhooks 文档](https://docs.stripe.com/webhooks)

## 易支付 / ZPAY

按提供的 ZPAY `submit.php`、`mapi.php`、`api.php` 文档对接，使用 MD5 签名。服务商文档中的当前示例域名为 `https://zpayz.cn`；Python 参考中的 `z-pay.cn` 是另一示例地址，程序不写死域名，以你在商户平台确认的网关为准。

### 后台配置

在「支付渠道 → 易支付 → 配置渠道」填写：

| 字段 | 填写内容 |
| --- | --- |
| 网关地址 | 例如 `https://zpayz.cn`；也可粘贴 `/submit.php`、`/mapi.php` 或 `/api.php` 完整地址，保存时自动归一化。不要粘贴带 PID / Key 参数的查询链接 |
| 商户 ID（PID） | 服务商分配的商户编号，支持字母和数字组合 |
| 商户密钥 | 对应 PID 的 MD5 签名密钥；已保存密钥以星号显示，留空沿用 |
| 支付类型 | 文档支持 `alipay`（支付宝）、`wxpay`（微信）；兼容选项 QQ 钱包、财付通仅在服务商实际支持时使用 |
| 下单模式 | 默认页面跳转 `submit.php`；也可选择 API 下单 `mapi.php` |
| 页面跳转方式 | 默认 POST 表单，GET 链接为兼容模式；只在页面跳转模式显示 |
| 支付渠道 ID | 可选，对应 `cid`；多个 ID 用英文逗号分隔，留空由平台选择 |
| 收银台网站名称 | 可选，对应参考代码的 `sitename`；留空使用当前主站或分站名称，仅用于页面跳转模式 |

当前配置卡片对应一种支付类型；仍不提供多个同名易支付实例。对外名称和 Logo 只改变顾客看到的展示，不改变实际支付类型。

### 页面跳转与 API 下单

页面跳转模式由后端生成已签名字段，浏览器向 `submit.php` 提交 POST 表单，商户密钥不会发送给浏览器。GET 兼容模式对签名后的参数逐项进行 URL 编码，中文、空格、`&` 和 `+` 不会因拼接 URL 而改变含义。

API 模式由后端使用 `multipart/form-data` 向 `mapi.php` POST 请求，提交实际套餐名称、准确到分的人民币金额、客户端 IP、设备类型及可选渠道 ID。渠道响应按 `payurl`、`qrcode`、`img` 顺序处理：有收银台地址时跳转，否则显示本站生成的二维码或渠道二维码图片。扫码后使用「刷新订单」查看是否到账及发货。

实际商品名称取自购买时的订单快照，后续改名不改变该订单的商品标题。签名按非空字段名排序，排除 `sign`、`sign_type`，以未 URL 编码的 UTF-8 字符串拼接密钥后计算 MD5；不使用浮点数换算金额。

### 通知与付款返回

以主站 `https://shop.example.com` 为例：

```text
异步通知：https://shop.example.com/api/v1/pay/notify/epay
浏览器返回：https://shop.example.com/api/v1/pay/return
```

两者均不携带查询参数，通过下单请求自动传递。若商户后台要求域名白名单，也需配置主站对应域名。分站订单仍集中回调主站；同步返回接口根据平台回传的 `out_trade_no` 跳回原分站的订单查询页。

升级前缓存的、返回地址带查询参数的旧 `submit.php` 链接，会在再次发起付款时重新签名修正，沿用原订单，不额外调用 API 创建第二笔交易。

只有已验签、PID 正确、`trade_status=TRADE_SUCCESS` 且订单金额一致的异步通知才能入账和发货；重复通知只记一次收款、发一次货，成功后返回纯文本 `success`。浏览器跳回订单页只用于导航，不会将订单标记为已付款。

### 对账与退款

对账通过 `GET api.php?act=order` 查询，优先使用 API 返回的渠道交易号，尚未收到交易号时按原商户订单号查询。API 超时或响应损坏后保留对账线索，避免盲目再次下单。查询同时核对返回订单、金额及返回的商户 ID。

未发货的已付款订单支持「易支付原路全额退款」，通过 `POST api.php?act=refund` 提交 PID、密钥、原商户订单号、渠道交易号及全额金额。商户须已开通服务商的退款能力。渠道明确返回 `code=1` 后才登记成功；已发货订单仍使用售后退款登记。

文档未提供退款幂等键或退款查询接口。网络超时、无法解析响应或渠道未确认成功时，订单保持退款待确认并暂停发货；同一申请不会自动重发，重复提交也会被阻止。请先到商户平台核实并按实际结果处理，确认已退款后使用「已在渠道退款，登记凭证」补全记录。原路退款结果不明确时不要同时在多个入口重复发起。

## DujiaoPay

使用 [DujiaoPay 文档](https://www.dujiaopay.com/docs) 对应的 HMAC API 与独立 Webhook 签名协议，不是 PHP「独角数卡」的支付插件配置。

### 1. 创建 API 凭据和 Webhook

在 DujiaoPay 商户后台取得 API Key ID 与 API Secret，再创建订单到账 Webhook：

```text
https://shop.example.com/api/v1/pay/notify/dujiaopay
```

订阅订单支付成功事件 `order.paid`，记录独立的 Webhook Secret。当前下单请求不会通过请求体传递 Webhook URL，**必须在 DujiaoPay 商户侧登记这个地址**。

### 2. 填写 Wybo 后台

| 字段 | 填写内容 |
| --- | --- |
| API 地址 | `https://www.dujiaopay.com`，或平台明确提供的 API 根地址；不追加 `/v1` |
| DJP Key ID | 商户 API Key ID |
| API Secret | 与 Key ID 对应的请求签名密钥 |
| Webhook Secret | 商户 Webhook 独立签名密钥，不能拿 API Secret 代替 |
| 指定链 | 可留空，或填写平台提供的准确链标识 |
| Token ID | 可留空；指定时必须与 chain 同时填写 |

`chain` / `token_id` 同时留空时，由托管收银台提供选择。当前请求为 `/v1/orders`，法币金额使用 `CNY`；回调校验 `DJP-Webhook-Timestamp` 与 `DJP-Webhook-Signature`，验签时间窗口要求服务器时间准确。

使用平台可用的测试环境或你确认的小额交易验证，检查平台订单、`order.paid` 投递、本店入账、发卡状态和金额。平台接口或商户参数与文档版本不一致时，应先核对协议再启用收款。

## BEpusdt

BEpusdt 是**独立的自托管收款网关**。本商城部署脚本不安装它，也不管理链上钱包；需要先按照 [BEpusdt 项目](https://github.com/v03413/BEpusdt) 部署并配置网关的钱包、网络监听和汇率，再连接 Wybo。

| 字段 | 填写内容 |
| --- | --- |
| 网关地址 | 例如 `https://usdt.example.com`，不追加 `/api/v1` |
| API Token | BEpusdt 实例配置的 `api_token` |
| 交易类型 | 例如 `usdt.trc20`，以你的网关版本及钱包配置支持为准 |

请求由商城提交到：

```text
POST https://usdt.example.com/api/v1/order/create-transaction
```

`notify_url` 随请求自动提交为本店完整回调地址，`redirect_url` 为本店订单返回地址。网关必须能从公网回调商城，顾客也必须能打开网关返回的收银台地址。

商品价格仍为人民币；请求的 `amount` 是 CNY 法币金额，`fiat=CNY`，并非直接把 ¥115 当作 115 USDT。网关根据汇率确定链上实际支付金额，顾客应严格按收银台显示的网络和数量支付。

当前回调按项目文档的 JSON MD5 `signature` 验签，`status=2` 才记为成功，使用回调 `amount` 校验人民币订单金额；`actual_amount` 是链上币量，不能替代本店人民币实收。API Token 必须与网关完全一致。

当前文档未提供可用的主动查单接口，因此本店 BEpusdt 渠道**没有自动查单补单能力**。优先在网关查看通知日志并重发真实回调；未确认交易不要在本店随意标为已支付。链上退款需要在实际钱包 / 网关侧处理后登记。

参考：[当前对接的 API 文档](https://github.com/v03413/BEpusdt/blob/main/docs/api/api.md)

## 每个渠道的验收顺序

1. 创建仅用于验收的商品，设置售价、真实测试成本并导入可识别的测试卡密。
2. 在前台完成下单，检查金额、优惠、渠道和跳转域名。
3. 用平台沙箱，或你明确确认的小额真实支付完成付款。
4. 在支付平台确认成功与回调投递记录，再检查本店「订单管理」「支付对账」及「上线检查」。
5. 核对只发出一次卡密、库存减少、成本 / 手续费 / 利润口径正确。手续费未知时先补全，不把它假设为零。
6. 重发同一条真实成功事件，确认没有重复发卡；验证未付款超时会释放库存。
7. 需要退款时，按对应渠道和订单状态执行支持的流程，核对平台实际退款结果与本店记录。

只有已验签并成功入账的回调才会成为后台联调证据。保存配置、显示渠道、浏览器跳回订单页，都不能单独证明收到款项。

当前已实现 Stripe 和易支付未发货订单的原路退款；易支付不自动重试结果未确认的退款。已发货售后采用实际退款后的登记流程，其他渠道以实际退款凭证为准。后台页面会根据订单状态提供对应操作。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 前台看不到支付渠道 | 必填密钥是否完整、是否已启用、是否使用当前正式域名 |
| 付款完成但订单仍待付款 | 服务商 Webhook / 通知投递日志、完整回调路径、WAF / 缓存、金额与币种 |
| 回调 404 / 502 / HTML 页面 | Nginx `/api/` 是否正确转发后端；后端是否正常运行；不要把 API 请求回退到 SPA |
| Stripe 验签失败 | 模式是否一致，是否填写了这个目的地的 `whsec_…`，服务器时间是否同步 |
| Stripe 收银台没有支付宝 / 微信 | Stripe 是否已开通、当前账户地区 / 币种 / 顾客条件是否支持、Wybo 是否手动排除了该方式 |
| Stripe `amount_too_small` | 测试订单是否过小、账户结算币种及换汇后是否达到最低门槛；改价后重新创建订单，不复用原小额订单 |
| Stripe 支付宝「买家认证不通过」 | 核对渠道，读取 PaymentIntent 失败码；按支付宝提示核实买家账户，并在 Stripe 正式环境检查 Alipay 能力及失败详情 |
| 易支付验签失败 | PID / MD5 密钥、网关协议、参数是否被代理修改 |
| DujiaoPay 验签失败 | Webhook 独立密钥、时间戳、商户 Webhook 地址 |
| BEpusdt 无通知 | 网关监听和钱包状态、API Token、网关到商城的网络与回调重试日志 |
| 已支付但待发货 | 库存是否不足，查看支付异常与待发货列表；不要重新创建付款来“补单” |
| 改 JWT_SECRET 后密钥读取失败 | 恢复配套的原加密密钥；不能单靠重新部署重置 |

检查服务日志时避免公开完整密钥、Webhook 请求签名、卡密或顾客联系方式。需要联系支付服务商时提供订单编号和已去除敏感内容的错误信息。
