# 代理分站

代理分站与主站运行在同一套服务器、程序和 PostgreSQL 中。每个分站使用独立子域名、品牌和管理账号，前台复用主站商城，后台仅管理自己的经营数据。新增分站无需新建服务器或逐个申请证书。

## 入口与权限

以主站 `shop.example.com`、分站根域名 `example.com` 为例：

| 地址 | 用途 |
| --- | --- |
| `https://shop.example.com/admin` | 主站后台，沿用已设置的自定义入口 |
| `https://shop.example.com/apply` | 公开分站申请页 |
| `https://alice.example.com` | Alice 的独立商城 |
| `https://alice.example.com/admin` | Alice 的分站后台 |

分站后台提供经营概览、商品定价、订单、售后工单、收益结算、店铺设置和账号安全。代理可以上架授权商品、修改零售价、上传本店 Logo / 浏览器图标、设置客服及兑换说明，修改密码并自行绑定 2FA。

主站采购成本、总库存卡密、支付密钥、全站设置和其他分站的数据不向代理开放。顾客查单必须在下单时的店铺域名下使用订单号及原联系方式；主站管理员仍能在总后台处理全部订单。

原来的推广代理、推广链接、佣金和历史结算继续保留。新分站单独开通，使用差价收益，不会与推广佣金叠加。当前不自动将已有推广代理账号迁移为分站。

## 为已部署站点启用分站

先保留现有部署的完整备份，拉取更新：

```bash
cd /root/Wybo
git pull --ff-only origin main
sudo bash deploy.sh backup
```

### 1. 配置 Cloudflare DNS

在管理 `example.com` 的 Cloudflare DNS 中，将 `*.example.com` 指向现有服务器公网 IP。保留主站记录；显式存在的子域名记录优先于通配符，请确认它们没有指向其他服务器。

脚本的 `--station-root` 可以使用主站域名本身或其直接父域名。例如主站为 `shop.example.com`，可使用 `example.com`，得到 `alice.example.com`；也可使用 `shop.example.com`，得到 `alice.shop.example.com`。使用后者时，普通 `*.example.com` 证书不覆盖 `alice.shop.example.com`，需按下面步骤为正确层级申请证书。

`www`、`admin`、`api`、`mail`、`shop` 等基础设施名称以及主站正在使用的子域名不能用于创建分站。未登记的子域名不会回退到主站商城。

### 2. 准备证书所需的 DNS API Token

在 Cloudflare 创建仅作用于对应 Zone 的 API Token，授予 Zone DNS Edit 与 Zone Read 权限。Token 用于 Certbot DNS 验证及自动续期，不填写到代理后台，也不发送到聊天中。

在服务器创建权限为 600 的文件，并用编辑器填入 Token：

```bash
sudo install -m 600 /dev/null /root/wybo-cloudflare.ini
sudoedit /root/wybo-cloudflare.ini
```

文件内容：

```ini
dns_cloudflare_api_token = 在这里填写你的API_Token
```

### 3. 更新并启用泛域名 HTTPS

```bash
cd /root/Wybo
sudo bash deploy.sh update \
  --station-root example.com \
  --cf-dns-credentials /root/wybo-cloudflare.ini
```

脚本校验并复制凭据到 `/etc/wybo/cloudflare.ini`，安装 Certbot Cloudflare DNS 插件，将原证书更新为覆盖 `example.com` 与 `*.example.com` 的证书，主站也在其覆盖范围内。已有证书名称及路径保持不变；域名集合变化时重新签发，后续更新按证书有效期复用。HTTP 跳转保留当前分站域名，API 转发也保留 Host。

原数据库密码、管理员密码、JWT 密钥和 2FA 保持不变。分站相关表由应用自动迁移。脚本将分站根域名保存在 `/etc/wybo/deployment.json`，以后普通更新即可：

```bash
git pull --ff-only origin main
sudo bash deploy.sh update
```

DNS Token 的服务器副本需保留供 Certbot 自动续期使用，并随 `/etc/wybo` 私密备份。更改分站根域名需要单独安排域名迁移，脚本拒绝直接覆盖已启用的根域名；已有订单保留原下单域名用于付款返回。

配置预览不需要真实 DNS Token，不会联网或改动服务器：

```bash
bash deploy.sh --dry-run \
  --domain shop.example.com \
  --email ops@example.com \
  --station-root example.com \
  --output-dir /tmp/wybo-station-preview
```

## 开通与审核

主站店主在「代理分站」中操作，其他团队角色默认没有分站管理权限。

- 手动开通：填写子域名、店铺名称、品牌简称、激活邮箱和结算等待天数。
- 开放申请：在该页启用公开申请，商城页脚出现「申请代理分站」入口。用户填写资料后等待审核；同一邮箱或子域名已有待审核申请时不能重复提交。
- 审核开通：在「申请审核」核对资料，设置结算等待期后开通；拒绝申请时可以记录审核说明。
- 账号激活：系统生成 48 小时有效、仅能使用一次的激活链接。代理打开后自行设置 12–72 字节密码，不由邮件传输明文密码。

主站开启 Resend 并配置有效发件域名后，后台通知任务会发送开通邮件，失败会重试并显示状态。未开启邮件时，店主可复制创建后显示的激活链接交给对应代理。激活链接属于账号凭据，不要公开；只在创建或重新生成时展示，重新生成会使旧链接失效。

已经激活的账号不再发放首次激活链接。代理忘记密码时，店主在「账号管理」验证主站身份后重设密码；遗失验证器时可单独解除 2FA。重设密码不会自动解除 2FA，两种操作都会撤销已有登录。

## 商品与发货

1. 主站为分站逐项授权商品，填写供货价；可同时填写初始零售价并设置是否上架。
2. 代理在自己的后台查看授权商品，设置不低于供货价的零售价，选择上架。
3. 顾客在该分站下单，系统从请求域名确定归属，不接受前端指定其他分站或代理来改变归属。
4. 自动发货商品使用共享库存与原有预占、付款发卡流程；手工发货订单由主站完成交付。

取消商品授权、分站下架或主站下架都会阻止新订单，不改变已经成立的订单。提高供货价时，零售价仍须满足供货价要求，必要时先取消上架。有关联分站价格的商品不能直接删除。

暂停营业只阻止新订单。已有订单仍可查询、付款、收到经验证的到账回调并完成发货，也可继续提交售后。主站处理退款或补卡，代理可以回复自己店铺的客户工单，但不能查看主站内部备注。

第一版分站不使用主站优惠券，也不自动创建升级补差订单；涉及套餐升级时由主站与顾客核对后使用新的独立订单处理，保留原订单财务记录。

## 收益与结算

第一版固定使用主站统一收款，支付手续费由主站承担。分站不能配置自己的支付密钥或钱包。

| 项目 | 示例金额 |
| --- | --- |
| 主站采购成本 | 105 元 |
| 分站供货价 | 110 元 |
| 分站零售价 | 115 元 |
| 代理差价收益 | 5 元 |
| 主站收益，扣支付手续费前 | 5 元 |

代理只能看到供货价，不会看到主站的采购成本。订单保存供货总额、成交金额、差价与手续费承担方式，后续调价不重算旧订单。主站经营净利润会扣除代理差价和支付手续费；费用尚未录入时仍提示资料不完整。

订单完成交付并度过主站设置的等待期后，代理可验证密码及已启用的 2FA 申请结算。事务锁定关联订单，避免重复申请。主站通过现有「代理结算」页面核对，在外部实际打款后登记凭证；系统不会自动转账。

退款会取消未结算收益。待打款结算单中的订单先取消结算再登记退款；已实际打款的差价仍保留为已发生支出，不假设已经从代理追回，后续由主站按真实处理结果核对。

经营概览显示累计实收、分站收益、付款订单数和近 30 天流量。订单页支持分页查看全部记录，概览只展示最近订单。流量按分站归属统计，UV 使用每日匿名指纹，不存原始访问 IP。

## 人机验证与邮件

分站继承主站 Turnstile 公钥与服务端密钥。Cloudflare Turnstile 控制台需要允许对应主站和分站域名访问；启用后分别验证主站申请页和分站下单页。服务端精确核对当前店铺的 hostname 与对应 action，分站之间不能混用验证结果。

付款通知仍集中进入主站的支付回调地址，到账后按原订单的分站归属处理，浏览器返回原分站订单页。不要给回调接口添加浏览器挑战。分站默认兑换入口与说明也用于发货邮件。

## 本地验证

在本地配置中设置 `SERVER_PUBLIC_HOST=shop.localhost`、`SERVER_STATION_ROOT=localhost`，将站点正式地址设为实际开发端口，例如 `http://shop.localhost:5173`。开发服务器需保留请求 Host；当前 Vite 代理已按此配置。浏览器需能将 `shop.localhost`、`alice.localhost` 解析到本机，必要时自行配置 hosts。

本地测试使用临时数据库，不向正在营业的数据库导入演示分站或测试订单。

自动化验证覆盖域名解析与 Host 伪装、跨站订单及令牌访问、商品授权与价格下限、图片归属、激活重放、2FA 与会话撤销、差价快照、重复回调、暂停营业后的原订单服务，以及退款与结算约束。公网 DNS、商户真实支付、Resend 实际投递及泛域名证书申请仍需使用正式配置验收。
