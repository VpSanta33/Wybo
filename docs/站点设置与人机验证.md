# 站点设置与 Cloudflare 人机验证

登录后台，进入「站点设置」。页面分为「基本信息」「下单防护」「邮件与推送」「支付地址」四个标签页，每页独立保存；标签旁的小圆点表示有未保存修改。可用左右方向键切换标签。

## 网站名称、Logo 与兑换地址

在「基本信息」修改：

| 配置 | 生效位置 |
| --- | --- |
| 网站名称、品牌短名称 | 首页、订单页、商家后台、代理工作台和浏览器标题 |
| 网站 Logo | 店铺与工作台品牌区域，未上传时显示默认月兔 |
| 浏览器图标 | 浏览器标签，未上传时显示默认月兔图标 |
| 网站简介、公告、客服、页脚 | 店铺介绍、首页公告、帮助内容、页脚 |
| 默认兑换地址 | 未单独配置兑换地址的商品，其订单页和发货邮件使用此入口 |

图片支持 PNG / JPG / GIF，最大 2 MB、最大 4096 × 4096。Logo 建议使用正方形透明底，浏览器图标建议 64 × 64 或 128 × 128。上传后预览，再点击「保存基本信息」生效；「恢复默认」也需保存。上传图片随服务器 uploads 目录备份。

默认兑换入口为 `https://cdk.fksanta.cc/`，可修改或清空。「商品与定价 → 编辑商品」单独填写的兑换地址优先于站点默认地址；两处均为空时，订单页引导顾客联系店主。旧订单读取当前兑换配置，修改后无需重发卡密。已经发出的邮件内容不会被追溯修改。

## 自行配置 Turnstile

**人机验证默认关闭。** 域名、Site Key 和 Secret Key 均由店主在后台自行配置，部署脚本不代开 Cloudflare 组件。

1. 打开 [Cloudflare Turnstile 控制台](https://dash.cloudflare.com/?to=/:account/turnstile)，添加小组件，选择 **Managed** 模式。
2. 添加实际使用的网站主机名，例如 `shop.example.com`，不要填写 `https://`、端口或路径。Turnstile 无需将网站 DNS 代理到 Cloudflare。
3. 在「站点设置 → 下单防护」填写「网站正式地址」，例如 `https://shop.example.com`，再填写该组件的 Site Key 和 Secret Key。
4. 开启「下单人机验证」，点击「保存下单防护」。缺少域名或任一密钥时，系统会拒绝开启。
5. 打开正式网站，选择商品、填写邮箱并核对订单，检查验证组件是否正常显示；完成验证后才能提交订单。部署后需用自己的有效密钥验收。

Site Key 是公开配置；Secret Key 仅在服务器加密保存，后台读取时显示遮罩。编辑其他配置时，保留 `********` 或留空会沿用已有密钥。请直接在后台填写 Secret Key，不要发到聊天或提交到 Git。

服务端严格核对验证结果的主机名与「网站正式地址」，并要求用途为 `checkout`。`example.com` 与 `www.example.com` 属于不同主机名，应将访客统一跳转到配置的正式域名；仅在 Cloudflare 中同时添加两个主机名，不能代替网站的统一跳转。迁移域名时同步修改 Cloudflare 允许的主机名和此地址；付款回调、返回地址及支付商户 Webhook 也需单独更新。

「上线检查」中的站点域名与此处的网站正式地址使用同一设置。开启验证后，从任何管理入口修改它都会影响主机名校验。

## 下单保护与异常处理

- 网页在确认订单时加载官方 Turnstile 组件；验证未通过、过期或加载失败时禁用「提交订单」，并提供重新加载入口。
- 服务端调用 Cloudflare Siteverify 验证令牌。直接调用下单 API 同样必须通过验证；失败时不会创建订单或预占库存。
- 令牌由 Cloudflare 限制为单次使用、有效期 5 分钟。重复或过期的令牌需重新获取；订单提交失败后网页也会重新验证。
- 校验服务最多等待 6 秒；网络异常、Cloudflare 返回失败或主机名 / 用途不匹配时均拒绝本次下单。
- 已有订单付款、支付平台异步回调不经过此组件。现有下单 API 每 IP 每分钟 10 次的频率限制继续生效。

Turnstile 可减少自动化占单，不能保证阻止所有恶意行为。后台管理员 2FA 仍由店主在「安全设置」单独启用，与顾客下单验证互不替代。

如使用自定义 CSP，请按 [Cloudflare 官方说明](https://developers.cloudflare.com/turnstile/reference/content-security-policy/) 允许脚本和框架访问 `https://challenges.cloudflare.com`。浏览器需可访问该域名，后端需能访问同域名的 Siteverify HTTPS 接口。不要给支付回调添加浏览器人机挑战。

排查时先检查密钥是否来自同一组件、Cloudflare 主机名列表及正式地址是否一致，再检查浏览器网络 / CSP 和服务器出网。不要记录或公开 Secret Key、完整验证令牌。

## 邮件与支付地址

「启用成交推送」是 Bark、店主成交邮件和成交 Webhook 的总开关；仅开启 Bark 子开关不会发送成交推送。总开关关闭而已配置子渠道时，页面会明确提示，可开启总开关后保存。顾客发货邮件由邮件通知开关单独控制。

开启成交推送后，历史已付款订单若缺少通知，可到「支付管理 → 支付对账」点击对应订单的「核对渠道」。核对成功会补发遗漏通知，已发送的任务不会重复发送，也不会重复扣款或发卡；已有失败任务在「推送记录」中重试。

Bark 手机成交通知、Resend、店主成交邮件及 Webhook 位于「邮件与推送」标签页。Bark 支持默认或自建服务器，填写设备 Key、开启成交推送与 Bark 后保存，可发送测试通知；具体步骤见 [后台管理指南](后台管理.md#bark-手机通知)。支付回调基础地址和付款返回地址在「支付地址」标签页。渠道商户参数、对外名称和 Logo 仍在「支付渠道」页面，详见 [支付渠道配置指南](支付渠道配置指南.md)。

## 本次验证范围

自动测试覆盖配置保存、密钥加密与脱敏、直接绕过网页下单、失效令牌、主机名 / 用途不匹配及验证服务异常。浏览器检查覆盖图片上传与保存后刷新、标签切换、手机布局、无效测试密钥的失败反馈及提交锁定、关闭验证后的正常确认流程。未使用真实 Cloudflare 生产密钥或完成真实支付；正式域名上线后需自行验收有效密钥。

参考：[服务端验证](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)、[客户端渲染](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/)。
