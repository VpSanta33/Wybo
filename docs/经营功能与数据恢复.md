# Wybo 经营功能与数据恢复

本轮功能均使用数据库记录；后台没有销售、流量或佣金的演示数据。后台入口仍可在安全设置中自定义，下面以 `/admin` 为例。

## 利润与月报

- `/admin/reports`：按北京时间、订单支付月份汇总，支持 CSV 导出。退款回溯到原订单月份。
- 经营净利润 = 订单实收 − 退款 − 商品成本 − 手续费 − 代理佣金，尚未扣税费、服务器及人工费用。
- 在卡密导入表单填写**本批次单张成本**，发货时按实际分配卡密汇总订单成本。未记录批次成本时，使用下单时商品成本快照，标注估算；历史资料未知时保持未知。
- 支付渠道可配置手续费率（基点，100 = 1%）及每笔固定费用（分）。两项都明确填写（可以为 0）才会估算手续费，按笔向上取整至分。费率在创建支付申请时留存快照。
- 订单详情支持补录实际手续费。缺失成本或手续费的订单不会按零成本虚增净利润。
- 未发货全额退款不计商品成本，但已发生的手续费仍计入损益。
- 原有销售利润接口字段 `profit_cents` 保留，经营净利润使用 `net_profit_cents`。

## 对账与退款

`/admin/reconciliation` 展示支付申请、异常与退款记录。支付申请创建后保存渠道单号和费率快照；创建结果不确定时阻止重复创建同渠道申请，避免重复扣款。

- Stripe：先查 Checkout Session，再查 PaymentIntent，核对订单号、币种、实付金额。
- 易支付：支持按商户订单号查询（标准 `api.php?act=order`）。具体服务商须兼容此协议。
- DujiaoPay：按渠道 `order_id` 查询并校验人民币金额。
- BEpusdt：现有文档没有主动查询与原路退款接口，因此保留已验签回调处理及人工账单核查流程。
- 经渠道核验的漏单使用同一幂等付款与发货流程补单；不同流水重复支付会保留额外收款记录并生成异常，不重复发卡。
- 回调金额不符等异常可在核实后登记处理说明；登记处理不会凭空修改实际付款。
- 自动对账默认关闭。开启后，近 72 小时内未匹配的可查询支付申请每 5 分钟重查一次。

订单详情的渠道退款仅适用于**已支付但未发货**订单；已发货全额退款登记见「售后处理」。订单详情提供：

1. Stripe 原路退款：使用官方 `/v1/refunds`，持久化退款申请与幂等键。只有渠道返回 `succeeded` 才标记已退款；`pending`/网络不确定结果继续保持退款处理中并暂停发货。重新提交会查询或继续原申请。
2. 渠道退款登记：其他渠道先在其商户系统完成退款，再填写真实退款凭证并确认。此功能登记结果，不会调用未经文档确认的退款接口。

暂不支持已发货卡密的自动退款、部分退款或自动撤销已发出的卡密。重复收款需要单独在渠道处理并记录异常说明。

## 库存预警与补发

`/admin/stock` 展示采购批次与库存告警，卡密正文仍在卡密库存页面默认遮罩。

- 导入完成后立即尝试待发货订单，运行中的后台另每分钟重试。订单按创建顺序处理，无法满足数量的订单继续等待；后续订单仍会检查。
- 使用订单事务和卡密状态条件更新，补发失败不会留下部分发卡或重复扣库存。
- 库存恢复后解除告警，再次不足会开启新一轮提醒。每轮提醒使用固定 Resend 幂等键，失败最多尝试 5 次。
- 低库存邮件默认关闭。在日志与运维设置启用，并在邮件与推送页配置 Resend、发件邮箱与商家接收邮箱。

## 代理与结算

- 分销代理资料中配置专属售价、佣金比例、结算等待期。佣金按优惠后的订单实收计算，并留存到新订单，改比例不会重算旧订单。
- `/admin/settlements` 分别展示可结算、等待期内、待打款及已打款金额。只有已发货且付款超过等待期的订单可结算。
- 生成结算单时事务锁定订单佣金，防止重复结算。外部实际转账完成后，登记凭证并确认，网站不会自动向代理转账。
- 在该页面设置代理工作台密码。代理通过 `/agent` 使用代理码登录，只能读取自己的推广订单、佣金和结算；不返回客户联系方式、卡密或商家采购成本。
- 代理令牌使用独立签名域和 audience，不能用于管理员接口。改密码会撤销旧代理登录，停用代理后旧令牌也不可使用。

## 营销与售后

- `/admin/coupons` 支持固定减免、折扣、订单门槛、起止时间、使用次数和指定商品。
- 可一次生成 1–200 个随机优惠码并导出 CSV。随机码由系统安全随机数生成。
- 优惠券次数在创建订单时占用，取消/超时自动回收，晚到的已验签付款重新记入使用；历史订单已引用的优惠券请停用保留记录。
- 顾客在「我的订单」通过订单号与原联系方式查询后提交工单、继续留言和查看公开回复。
- `/admin/tickets` 查看关联订单、回复顾客、记录内部备注，标记处理中、等待回复或已解决。客户不可读取内部备注或回复其他订单的工单。

## 日志与备份

`/admin/maintenance` 记录管理员变更、订单详情和卡密读取、备份下载等操作；保留操作人、接口、对象、时间与业务结果，不记录请求正文、密码、API 密钥或卡密。

SQLite 备份通过 `VACUUM INTO` 生成一致性快照，包含已提交的 WAL 数据。快照目录权限 0700，文件权限 0600，保存大小和 SHA256；下载与准备恢复时重新校验。

自动备份默认关闭，可设置 1–720 小时间隔；服务运行时每分钟检查是否到期。可在运行监控页配置定时快照保留天数；默认不清理，始终保留至少最近 3 份有效定时快照及所有手动快照。PostgreSQL 应使用数据库运维备份（例如 `pg_dump`），此内置工具不执行 PostgreSQL 恢复。

### 恢复步骤

1. 在备份记录中选择「恢复指引」，获取文件名、SHA256 和准确命令。
2. 停止**所有使用该数据库的后端进程**。
3. 在 `backend` 目录执行页面给出的命令，例如：

   ```sh
   go run ./cmd/db-restore --backup data/backups/wybo-<文件名>.db --sha256 <页面中的校验值>
   ```

4. 工具获取独占维护锁，校验 SHA256、SQLite 完整性和必要表结构，先生成 `wybo.db.before-restore-<时间>.db`，再替换数据库。
5. 使用原来的 `JWT_SECRET` 重新启动后端，以读取已有加密配置。恢复后的数据库会在启动时迁移到当前结构。

恢复不通过网页直接覆盖运行中的数据库。运行中的新版后端持有共享维护锁，恢复工具会拒绝并提示先停服。回退恢复时可对恢复前快照计算 SHA256，并使用同一工具恢复。

## 验证

- 前端 TypeScript 与生产构建通过；经营图表按页面延迟加载。
- Go 测试覆盖批次成本、未知费用、实际手续费、重复付款、漏单核验、退款凭证、优惠范围、佣金结算、防重复打款、代理权限、内部工单隐私、备份校验及维护锁。
- Stripe 退款与查询使用模拟 HTTP 验证请求和幂等键，无真实退款。
- 临时数据库验证恢复成功、保留恢复前快照及错误校验值被拒绝。
- 使用独立数据库检查有成交、有代理结算和工单的页面；正式数据不添加演示经营记录。375px 手机和 812px 横屏检查无页面横向溢出。
