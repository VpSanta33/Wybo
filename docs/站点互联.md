# Wybo 站点互联

站点互联用于两套独立部署的 Wybo 之间供货。每个站点既能向上游采购，也能创建下游采购账户供货。下游订单由本站卡密库存交付，或由指定上游履约，再逐级返回交付结果。

后台入口为「站点互联」，包含上游连接、商品对接、下游账户、订单任务和资金流水五个标签。现有「代理分站」用于本站托管的店铺；互联钱包与代理佣金、分站差价分别记账。

## 第一版范围

- 双方更新至支持互联的 Wybo 版本，使用 Wybo 自有互联协议。
- 采购币种为人民币 CNY，支持自动交付卡密 / 账号密码，每单一种商品，可购买多份，整单交付。
- 每个本地商品绑定一个上游；本地库存商品仍按原流程销售。
- 受理下游订单时正式扣钱包余额；明确失败后用独立退款流水退回原账户。
- 上游人工充值表单、部分交付、多上游拆单和自动切换供应商不属于第一版自动履约范围，此类售后需人工核查。

## 配置前准备

两站更新后，数据库表在后端启动时自动迁移。生产站点使用可公开访问的 HTTPS 地址，上游地址和回调地址不能指向 localhost、内网地址或服务器本机服务。

互联页面显示本站标识，用来识别站点、防止向自身采购和循环供货。请保持数据库及 `JWT_SECRET` 稳定；互联密钥与现有支付配置一样，需要随数据库妥善备份。

## 两站首次连接

下文将供货站称为 **B 站**，采购站称为 **A 站**。

### 1. B 站创建下游账户

进入 B 站「站点互联 → 下游账户」，点击「新增下游」，填写 A 站名称并启用账户，回调地址可以暂时留空。

保存本次显示的 API Key 和 API Secret，交给 A 站。Secret 仅在创建或轮换时展示。丢失密钥时使用「轮换凭证」，并在 A 站更新；旧凭证立即失效，账户余额和原有订单保持不变。

### 2. B 站登记充值和商品授权

在账户行点击「充值登记」，核实实际收到付款后填写到账金额、唯一付款流水和备注。该操作只登记钱包入账，不会自动从外部银行卡或支付账户扣钱。重复付款流水不能重复增加余额。

点击「商品授权」，逐项选择允许 A 站采购的商品，设置专属供货单价并启用。A 站只能看到授权范围内的可售商品及自己的供货价，不能查看 B 站采购成本或其他账户价格。

本地自动发货商品需要先导入可售卡密；B 站若将商品对接到更上游，则按其有效供货配置处理。

### 3. A 站添加上游并同步

进入 A 站「站点互联 → 上游连接」，点击「新增上游」，填写 B 站根地址、连接名称、API Key 和 API Secret，并启用连接。

保存后点击「测试连接」，核对上游身份与账户余额，再点击「同步商品」。测试失败时检查双方版本、HTTPS、根地址、凭证和账户启停状态。

测试通过后，该连接固定对应原上游站点和采购账户。轮换凭证会验证账户身份；更换站点地址或采购账户时新增连接，再调整商品映射，避免旧订单重试时采购到另一个账户。

### 4. B 站补充回调地址

A 站保存连接后，将连接编号告知 B 站。B 站编辑对应下游账户，将交付回调地址设为：

```text
https://A站域名/api/v1/peer/callback/<connection_id>
```

`connection_id` 是 **A 站保存的该条上游连接编号**，不是 B 站的下游账户编号。例如 A 站连接为 `1`，回调为 `https://A站域名/api/v1/peer/callback/1`。

回调用于通知状态与交付结果；A 站也能通过查单核对结果。回调失败不会撤销已成功交付的订单。

### 5. A 站建立商品映射

先在 A 站「商品与定价」创建本地商品，设置分类、展示名称、售价和兑换说明。进入「站点互联 → 商品对接」，点击「对接商品」：

1. 选择本地商品和刚才建立的上游连接。
2. 选择同步返回的上游商品规格。
3. 核对最高采购单价，启用上游供货。
4. 按需开启同步本地零售价，填写成本加价比例和固定加价。

最高采购单价是新订单允许的采购上限，避免按超过预期的金额采购。订单保存当时的商品、供货来源与金额快照，后续修改映射或价格不重写旧订单。

关闭同步售价时保留 A 站自己的售价；开启时按“上游成本 ×（1 + 加价比例）+ 固定加价”计算。向下游供应的专属供货价在商品授权中单独管理。

## 订单与资金流程

A 站顾客付款后保存采购任务，后台向 B 站请求报价、下单。B 站检查授权、报价、库存和余额，在同一事务内创建订单、扣钱包、保存支付记录与履约任务。

B 站交付后，A 站核对订单归属、数量和金额，将卡密直接绑定到原顾客订单；不会先混入公共可售库存。顾客仍在 A 站原有订单查询入口领取。

B 站继续向 C 站采购时，订单向上请求、结果向下返回。来源链包含站点身份；重复经过同一站点或超过允许层数时拒绝采购。

后台金额输入以元显示，API 金额统一是整数分。例如 108 元提交为 `10800`，币种为 `CNY`，不能将以元计的浮点值直接提交。

充值、订单消费和退款分别留存流水。充值增加可用采购余额；订单扣款对应本层销售。上游采购成本、本站供货收入和下游自行决定的零售价不能混合记账。查看「资金流水」核对变动金额、变动后余额及付款凭证。

## 异常和售后

| 状态 | 含义和处理 |
| --- | --- |
| 待处理 / 处理中 | 后台正在受理、采购或查询，先查看最近结果 |
| 结果待确认 | 上游可能已接受请求，应查询原单，不能按失败退款或另开新单采购 |
| 明确失败 | 已明确拒绝或确认采购未成交，可核查后处理原下游钱包退款 |
| 已完成 | 交付已保存，通知失败只需重试回调 |

「查单 / 重试」仍围绕原采购单，不通过新外部单号绕过未知结果。API 以“稳定采购账户 + external_no”保证幂等；轮换密钥后重试同一外部单号也不应重复扣款。同单号但商品、数量等原始参数不同会拒绝。

钱包退款只退回原下游账户，原消费流水保留，另记退款流水，不能直接改写历史余额。普通商城顾客订单仍走订单售后及对应支付渠道退款。

已交付卡密、人工处理或取消结果不确定时，应结合原采购记录人工核查。不要仅凭超时或回调失败重复采购、退款或换卡。未知成本应保留待核对状态，不按零成本计算利润。

## 上线核对

先用独立测试账户和测试卡密跑通一笔订单，再核对：

- 商品、专属供货价、采购上限和库存符合预期。
- 重复下单不重复扣款，余额不足不产生成功消费。
- 超时可查询原单恢复，服务重启后任务继续执行。
- 重复回调不重复发货，回调不可用时仍可查到真实结果。
- 明确失败退款只入账一次，其他账户读不到本单或卡密。
- 本站不能对接自身，循环供货会被拦截。

互联双方都保留自己的订单、付款和交付记录，用于核对跨站链路。不要在日志或公开截图中展示 API Secret 和完整卡密。

## 协议与接口

协议版本为 `1.0`。机器接口前缀 `/api/v1/peer`，采用 JSON，成功响应为 `{"code":0,"message":"ok","data":...}`。错误同时返回非 2xx HTTP 状态和非零 `code`，资金或订单结果未知时返回服务端错误，调用方必须查原单。

每次请求带以下头：

| 请求头 | 内容 |
| --- | --- |
| `X-Wybo-Key` | 下游采购账户的 API Key |
| `X-Wybo-Timestamp` | Unix 秒级时间戳，与服务端相差不超过 5 分钟 |
| `X-Wybo-Nonce` | 每次请求独立生成的 16–80 字节随机串，重试也必须更新 |
| `X-Wybo-Signature` | 使用 API Secret 计算的 HMAC-SHA256，小写十六进制 |

签名原文的五段内容以换行符连接，末尾不再加换行：

```text
大写 HTTP 方法
完整请求路径（含 /api/v1/peer 前缀和原始查询串）
X-Wybo-Timestamp
X-Wybo-Nonce
SHA256(原始请求体字节) 的小写十六进制
```

GET 无请求体时，最后一段为 SHA256 空字节串的摘要。不要先签名再重新序列化 JSON，否则原始字节变化会导致认证失败。

| 接口 | 用途 |
| --- | --- |
| `GET /ping` | 站点身份、采购账户编号、协议版本、币种和钱包余额 |
| `GET /products` | 当前账户已授权的自动交付商品、专属单价、可售库存和来源链 |
| `POST /quotes` | 提交 `product_id`、`quantity`、`route`，取得 60 秒有效的报价 |
| `POST /orders` | 使用该报价及固定 `external_no` 受理采购并扣钱包 |
| `GET /orders/:externalNo` | 查询当前账户自己的采购单和交付结果 |
| `POST /orders/:externalNo/cancel` | 取消尚未采购或已明确失败的未交付订单，退款到原钱包 |
| `POST /callback/:connectionID` | 向采购站通知交付结果；使用双方同一采购账户凭证签名 |

下单提交 `external_no`、`quote_id`、`product_id`、`quantity`、`max_total_cents`、`route`。`external_no` 长度 1–120，只允许字母、数字和 `_.:-`；`quantity` 为 1–99；`max_total_cents` 必须等于已确认报价总额，单次不超过 `10000000000` 分。`route` 是当前采购已经过的站点标识，发起站将自己的标识作为第一项。

同一采购账户与 `external_no` 是稳定幂等键。响应丢失后保留原报价、单号和全部参数重试，不能用新报价重写旧请求；已有订单可在原报价过期后查询或按原请求重放。未知结果收到后续拒绝时，也必须先查原单确认。

订单回执含 `order_no`、`external_no`、`status`、`total_cents`、`currency`、`quantity`、`version`，完成时另带 `lines: [{"code":"卡密或账号","secret":"密码，可为空"}]`。受理状态版本为 `1`、完成为 `2`、退款为 `3`；回调结构为 `{"event_id":"...","version":2,"order":{...}}`。接收端核对连接、原单、报价、数量、版本和整单内容后保存交付，重复或较旧回执不会再次发货。
