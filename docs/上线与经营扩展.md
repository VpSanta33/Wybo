# Wybo 上线与经营扩展

这些功能使用真实数据库与服务端权限校验，默认入口为 `/admin`；自定义入口后，以下子路径保持一致。

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 上线检查 | `/admin/readiness` | 域名、HTTPS、管理员安全、付款回调、Resend、备份及商品准备情况 |
| 团队与权限 | `/admin/team` | 独立成员、店主 / 运营 / 客服 / 财务 / 库存角色、停用及密码重设 |
| 供应商与采购 | `/admin/procurement` | 合作资料、采购单、实际付款登记、整批卡密入库、供应商表现 |
| 售后处理 | `/admin/after-sales` | 同商品换卡、单份订单升级补差、已发货全额退款登记 |
| 运行监控 | `/admin/runtime` | 数据库、运行时内存及协程、业务告警、备份间隔和保留策略 |
| 转化分析 | `/admin/conversion` | 访问 → 选购 → 下单 → 付款、来源 / 活动、代理、未付款订单 |

## 库存预占与下单限制

- 待付款订单有效期 15 分钟，创建时事务预占具体卡密。`可售库存` 不包含预占卡密。
- 服务端按 IP 限制下单、查单和支付请求，同一联系方式最多存在 3 笔待付款订单。
- 取消或超时关闭同时释放卡密和优惠券容量，重复处理不会重复归还。
- 已预占卡密不能停用或删除；成功付款优先发出本订单预占的卡密。
- 已验签的晚到付款仍记作实收，不能拿走其他订单的预占库存。缺货时保留为已支付待发货，由补货任务继续处理。
- 晚到付款会重新记录优惠券使用；原优惠已承诺给已收款订单，因此使用计数可能超过后来重新分配的限额，不会改动已收款金额。
- SQLite 使用单连接及 WAL 模式串行化写事务；PostgreSQL 使用行锁和条件更新。启动迁移兼容历史订单，既有卡密不会重新分发。

## 团队与敏感操作

| 角色 | 主要权限 |
| --- | --- |
| 店主 | 全部功能；团队、支付密钥、站点设置及后台入口 |
| 运营 | 经营概览、商品、营销、订单与工单；客户联系方式遮罩 |
| 客服 | 只读商品、订单、工单、换卡与升级；没有成本、利润及明文卡密权限 |
| 财务 | 财务、支付只读、对账、退款、代理结算及采购只读；客户联系方式遮罩 |
| 库存 | 只读商品、库存、采购、换卡与升级；订单客户联系方式遮罩 |

- 每位成员自行在安全设置中更改密码和绑定 2FA。团队管理不会清除他人的验证器。
- 添加成员及重设密码要求 12–72 字节；停用、改角色或改密码后立即撤销旧会话。
- 不能停用或降级当前店主，必须保留至少一位启用的店主。
- 卡密列表和订单详情默认只返回遮罩。查看明文通过独立接口执行，并写入审计日志。
- 查看卡密、下载备份、成员变更、退款、采购付款登记、代理密码 / 打款、取消结算及清理备份会要求再次验证当前密码；已绑定 2FA 的成员还需验证码。
- 验证凭证仅在内存中使用，绑定当前管理员、会话版本与确切操作路径，有效期 2 分钟。密码、验证码、密钥、卡密正文不写入审计记录。

## 采购与供应商

1. 添加并启用供应商。
2. 新建采购单，填写商品、数量、单位成本及备注。
3. 外部实际付款后登记金额和唯一流水；系统不会发起转账，也不允许超额登记。
4. 按采购数量一次性入库卡密，每行一张。账号密码格式为 `账号----密码`。
5. 重复、空卡或数量不符整笔回滚；成功后生成关联采购单与供应商的库存批次，逐卡保存成本，随后尝试待发货订单。

已入库不可重复入库。仅未付款且未入库的采购单可取消。当前不提供分批收货、采购退货或供应商在线打款。

供应商表现按实际已发卡批次归属统计：同一订单的原卡与换发卡均摊收入，成本累计保留；退款扣减收入。毛利尚未扣支付手续费、代理佣金和经营费用，按分均摊可能产生尾差。采购单列表显示最近 200 单，付款记录最近 500 条。

## 售后与财务口径

- **换卡**：读取订单当前卡密编号，选择要替换的一张并填写原因。系统分配同商品可售卡，将原卡标记为已替换。客户查询只返回新卡，原卡不回收为可售；订单成本同时包含原卡和新卡。
- **升级补差**：仅支持已完成且当前有一张有效卡的订单。选择不同的、已定价的目标商品，填写约定补差金额，生成有效期 15 分钟的独立付款订单并预占目标库存。顾客可从原订单查看补差订单，用原联系方式付款。
- 只有补差订单成功付款并实际发卡后，原卡才标记为已替换；原订单保留原成本，补差订单承担新卡成本及自身渠道费和佣金。取消或超时释放目标卡。若已取消补差的晚到款与新申请冲突，将保留为待人工核查的已付款订单，不能覆盖另一笔升级。
- **已发货退款**：先在实际支付渠道完成全额退款，再登记真实凭证及原因；网页仅记录结果，不自动调用渠道退款。已发卡标记为退款卡，不重新出售；原卡、换发卡成本及实际手续费继续计入损益。
- 未结算佣金取消；已实际打款佣金继续计作支出，不假设款项已从代理追回。佣金若正在待打款结算单中，先在代理结算页取消该结算单，再登记售后退款。
- 未发货订单继续使用订单详情中的 Stripe 原路退款 / 外部退款登记流程，退款成功后释放仍预占的卡密。
- 利润与月报、仪表盘、订单详情采用一致的退款及成本口径。缺失成本或手续费仍显示待补全，不能按零成本计算利润。

关联升级订单须先退款或关闭，再处理原订单退款。

当前不支持部分退款、自动撤销上游已激活权益、自动追回代理款或已发货订单自动退款。

## 上线检查与真实验证

- 状态明确区分「待配置」「已配置」「待验证」「已验证」。不会通过创建假订单或假回调制造成功记录。
- 公网 HTTPS 检测只访问配置的 HTTPS 443 站点，验证 TLS 证书及 HTTP 响应；拒绝内网、保留网段及重定向跟随。
- 点击发送测试邮件会先弹窗确认，只发至已配置的商家通知邮箱。Resend 接受请求不等于收件箱最终投递成功。
- 成功付款回调只有在验签且入账成功后才留下联调证据。更换渠道配置或回调基础地址后，旧证据失效。
- 邮件、HTTPS、回调的联调证据有效期为 7 天；备份检查重新校验最新已登记快照的 SHA-256。开发时创建的目录外安全快照不伪装成已登记运维备份。
- 离线恢复演练需实际停服并执行恢复工具；快照可读不代表已演练恢复。

## 运行告警与备份策略

后台每分钟检查：超过 5 分钟未发货的已付款订单、失败或卡住的通知、未处理支付异常、结果未确认的退款、备份失败 / 过期 / 校验失败。

告警按一轮异常去重，恢复后关闭，复发重新开启。邮件默认关闭，启用后复用 Resend 及商家通知邮箱，每轮最多重试 5 次。运行页内存为 Go 已分配堆内存，不代表整机内存；协程数不是访问量。

- 定时备份间隔：0 关闭，1–720 小时。
- 保留天数：0 不自动清理，1–3650 天。
- 只清理数据库登记的、过期的 **scheduled** 快照，始终保留最近 3 份校验通过的定时快照；手动快照和开发安全备份保留。
- 手动「按策略清理」与自动任务执行同一规则。清理操作有审计记录；没有至少 3 份有效定时备份时不会清理。
- 内置快照及恢复面向 SQLite；PostgreSQL 需使用数据库运维备份。

## 转化分析

- 按上海时区的每日选购页浏览器会话去重，同一天同一浏览器会话同类事件不会重复累计。
- 页面访问、主动切换商品或进入下单核对记录前两步；下单来自服务端订单，付款来自服务端成功入账，浏览器不能上报付款成功。
- 漏斗按完整访问 → 选购链路关联；缺少访问 / 选购证据的历史或未归因订单单独计数。升级补差订单不增加获客下单数。
- `utm_source` 和 `utm_campaign` 在当前标签页首次进入时保存，支持来源 / 活动统计。来源只存主机名或清洗后的标签，不保留完整引荐 URL、查询参数或原始浏览器会话标识。
- 会话标识经每日 HMAC 处理；浏览器启用 Do Not Track 时不提交漏斗事件。
- 代理页按实际代理归属统计下单及付款率；未付款列表展示最近 100 笔待付款 / 已关闭订单。
- 此统计不是广告平台归因，不追踪跨浏览器身份，跨日访问按新会话计算。
