# Wybo 原生部署

入口脚本为项目根目录的 `deploy.sh`，使用 PostgreSQL、Nginx、Certbot 与 systemd。**不使用 Docker。**

## 服务器与域名

- 支持 Ubuntu 22.04 / 24.04、Debian 12 / 13，amd64 或 arm64；需要 root / sudo 与 systemd。
- 建议使用全新服务器，至少 2 核、2 GB 内存和 10 GB 可用磁盘；构建阶段建议 4 GB 内存。服务器需要能下载系统软件源、Go、Node 与 npm / Go 模块。
- 将 `shop.example.com` 的 A 记录指向服务器公网 IPv4。有 AAAA 记录时，IPv6 也必须指向本机并可访问。
- 云安全组放行 TCP 80 / 443，保留自己的 SSH 端口。申请证书前建议将 CDN 设为「仅 DNS」，避免挑战请求被缓存、防火墙或人机验证拦截。
- 本脚本不修改其他 Nginx 站点、不重设已有 PostgreSQL 超级用户密码。已有数据库角色或数据库名 `wybo` 与首次安装冲突时会停止。

## 上传与首次安装

将**完整项目**上传到服务器，例如 `/root/Wybo`，应包含 `backend/`、`frontend/`、`deploy/` 与 `deploy.sh`。本地 `node_modules`、`dist`、缓存和 `backend/data` 无需上传。

```bash
cd /root/Wybo
sudo bash deploy.sh install \
  --domain shop.example.com \
  --email ops@example.com
```

将示例域名和邮箱替换为自己的。脚本会询问一次安装确认；申请证书意味着同意 [Let's Encrypt 订阅协议](https://letsencrypt.org/repository/)。需要非交互执行时加 `--yes`。

也可以直接 `sudo bash deploy.sh`，按提示输入域名和证书邮箱。首次管理员用户名默认为 `admin`，可通过 `--admin-user moon_owner` 指定。

脚本依次完成：

1. 检查系统、源码、域名解析和后端端口。
2. 安装 PostgreSQL、Nginx、Certbot 及系统工具，设置开机启动。
3. 通过官方 HTTPS 下载独立 Node 22 LTS 与符合 `go.mod` 的 Go 最新补丁版，核对 SHA-256；不替换系统原有 Node / Go。
4. 以普通 `wybo` 用户运行后端测试和前端生产构建，构建内容不读取本地 `.env` 或演示模式。
5. 创建非超级用户数据库角色 `wybo` 和数据库 `wybo`。数据库密码、初始后台密码与 JWT / 配置加密密钥分别随机生成。
6. 配置 systemd 后端服务，只监听 `127.0.0.1:8080`；Nginx 提供静态页面、SPA 路由、API 和上传文件代理。
7. 自动建表、首次创建管理员，初始化正式站点及付款回调地址；已有后台配置不会被这些初始值覆盖。
8. 申请受信任的 SSL 证书，启用 HTTP → HTTPS 跳转、Certbot 自动续期及续期后的 Nginx 重载。
9. 检查真实证书与 HTTPS 健康接口，创建首份备份，启用每日备份。

首次创建的是**全新的生产数据库**，不会自动把本地 SQLite 的商品、卡密或测试订单迁入 PostgreSQL。上线商品、成本和库存请在后台录入；已有营业数据需要另行安排迁移。

## 获取密码与开启 2FA

安装成功后：

```bash
sudo cat /etc/wybo/credentials.txt
```

凭据文件只有 root 可读，脚本不把随机密码打印到安装日志。用其中的初始账号密码访问 `https://shop.example.com/admin`。

**2FA 不由部署脚本开启。** 登录后进入「安全设置」，使用验证器扫描二维码，输入当前验证码确认绑定；随后重新登录。改密码、修改后台访问地址也在此页面操作。服务器时间需同步，否则 TOTP 与支付回调时间戳验证可能失败。

初始密码只在数据库为空时使用。后台修改密码后，`credentials.txt` 中的初始密码不再代表当前登录密码；重复部署不会重置密码或 2FA。

网站名称、Logo 和兑换地址在「站点设置 → 基本信息」修改；Cloudflare Turnstile 默认关闭，由店主在「站点设置 → 下单防护」填写正式地址及两把密钥后开启。无需修改部署脚本，步骤与域名迁移注意事项见 [站点设置与人机验证](站点设置与人机验证.md)。

## 文件位置

| 路径 | 内容 |
| --- | --- |
| `/opt/wybo/releases/时间-随机串/` | 每次构建的后端程序与前端静态文件 |
| `/opt/wybo/current` | 当前版本软链接 |
| `/opt/wybo/toolchains/` | 独立 Go / Node 工具链 |
| `/etc/wybo/deployment.json` | 稳定的安装凭据与站点信息，权限 600 |
| `/etc/wybo/wybo.env` | systemd 读取的数据库 / 加密配置，权限 600 |
| `/etc/wybo/config.yaml` | 非秘密运行配置 |
| `/etc/wybo/credentials.txt` | 首次登录与数据库凭据，权限 600 |
| `/var/lib/wybo/uploads/` | 持久化上传文件 |
| `/etc/nginx/sites-available/wybo.conf` | 托管站点与反代规则 |
| `/etc/letsencrypt/live/你的域名/` | SSL 证书及私钥 |
| `/var/backups/wybo/` | 数据库、配置和上传文件备份，权限 700 |

`JWT_SECRET` 同时用于加密支付密钥、Resend Key 和 2FA 密钥，必须保持稳定并随数据库一起备份，**不要删除 deployment.json 或直接重新生成该密钥**。

PostgreSQL 默认使用本机连接和随机应用密码，`postgres` 超级用户通过服务器 OS peer 认证管理。脚本不对公网开放 5432 / 8080；发现数据库配置为公网监听时会停止，等待你核对现有业务。

## 更新版本

上传更新后的完整源码到原目录，再执行：

```bash
cd /root/Wybo
sudo bash deploy.sh update
```

无需再输入域名、邮箱或密码。更新先构建和测试新版本，再为旧版本创建数据库 / 配置备份，保留旧发布目录，最后切换软链接并重启服务。切换时会有短暂中断，支付渠道应保留重试回调。

- 构建失败时旧版本继续运行。
- 启动或数据库迁移失败时会明确报错；脚本不会擅自回滚数据库或清空数据。
- `/etc/wybo/previous-release` 记录前一个发布目录。只有确认数据库结构兼容，才可手动切回旧程序；涉及结构变更时，先在隔离数据库演练恢复。
- 每次更新会重新生成本项目管理的 Nginx / systemd 文件。自定义反代规则应维护在 `deploy/render.py` 模板中，避免更新丢失。

重复运行 `install` 也会沿用已有凭据与数据，不重新生成管理员密码或重置 2FA。不要用同一个 `deployment.json` 在仍运营的两台主机之间随意切换。

域名迁移需要人工安排窗口：先保留完整备份并配置新域名 DNS，通过 `sudoedit /etc/wybo/deployment.json` 仅修改 `domain`，保留所有随机密钥，再运行 `sudo bash deploy.sh update`。脚本会申请新域名证书并更新托管配置；原数据库内的站点和付款地址不会自动覆盖，需在后台「站点设置 → 下单防护」和「站点设置 → 支付地址」同步修改，并更新支付平台 Webhook。旧域名在途订单回调需另行保留转发，确认完成后再下线旧入口。

仅修改证书联系邮箱时，先执行 `sudo certbot update_account --email 新邮箱 --agree-tos`，再使用 `sudoedit` 仅更新 `deployment.json` 的 `email`。不要重建整个凭据文件。

## 日常操作与排查

```bash
# 查看状态与日志
sudo bash deploy.sh status
sudo journalctl -u wybo -f
sudo systemctl status nginx postgresql
sudo tail -n 80 /var/log/nginx/wybo-error.log

# 重启应用或检查 Nginx
sudo systemctl restart wybo
sudo nginx -t

# 验证续期（使用 ACME 测试环境）
sudo certbot renew --dry-run
sudo systemctl list-timers certbot.timer wybo-backup.timer

# 手动备份
sudo wybo-backup
```

Nginx 默认关闭此站点的访问日志，避免查单 URL 中的联系方式进入日志。应用经营流量仍由后台记录。

证书失败时检查：域名是否解析到本机、80 端口是否可从公网访问、AAAA 是否错误、CDN / WAF 是否拦截挑战、CAA 是否允许 Let's Encrypt。首次 SSL 完成前，HTTP 只开放证书挑战，其余请求返回 503；修复后重新执行安装即可。

后端失败时先看 `journalctl -u wybo -n 80`。确认 PostgreSQL 正常运行及 `/etc/wybo/wybo.env` 的凭据未被手工更改。端口被其他服务占用时，请核对该服务归属，脚本不会自动结束它。

## 备份与恢复

系统每天上海时间约 03:20 自动备份，结果目录包含：

- `database.dump`：`pg_dump` 自定义格式，一致性数据库快照。
- `config.tar.gz`：加密密钥、安装配置及初始凭据，包含秘密，需私密保存。
- `uploads.tar.gz`：上传文件；与数据库不构成跨文件系统的原子快照，严格一致性要求下先停后端再手动备份。
- `SHA256SUMS`、`COMPLETE` 和旧版本路径。

备份不自动删除，需定期监测磁盘并将完成的备份复制到可信的异地存储。后端内置的网页备份功能面向 SQLite；此部署使用的 PostgreSQL 备份由系统任务负责，不会伪装成后台已登记的 SQLite 备份或恢复演练。

先用独立数据库验证备份可恢复（以下名称是演练库，不覆盖线上库）：

```bash
# 使用实际完成的备份目录替换示例。以下命令在 root shell 中执行。
cd /var/backups/wybo/实际备份目录
sha256sum -c SHA256SUMS
sudo -u postgres createdb -O wybo wybo_restore_check
sudo -u postgres pg_restore --no-owner --no-acl --role=wybo \
  --dbname=wybo_restore_check < database.dump
sudo -u postgres psql -d wybo_restore_check -c 'SELECT count(*) FROM orders;'
```

演练完成不自动删除数据库。真正恢复营业库前，先停止后端、备份当前现场，再确定要恢复的时间点与配套 `config.tar.gz` / 上传文件；不要直接对运行中的生产库执行 `--clean`。恢复数据库时必须使用同一份 JWT 加密密钥，保持应用角色拥有表与序列。

## 账号恢复

发布目录包含 `admin-recover`，沿用应用的数据库和密钥配置。仅在服务器 root 会话中操作，不通过网站暴露。

```bash
sudo -i
cd /etc/wybo
# 文件由本脚本生成，只包含固定键名和校验过的值。
set -a
. /etc/wybo/wybo.env
set +a

# 只恢复入口，不改变密码或 2FA
/opt/wybo/current/bin/admin-recover --username admin --admin-path /moon-console

# 遗失验证器时，明确执行此命令才会移除 2FA
/opt/wybo/current/bin/admin-recover --username admin --reset-2fa
exit
```

更改后台密码优先使用后台安全页面。忘记密码时可使用同一工具的 `--password-stdin`，具体读取方式见 [后台管理](后台管理.md)。部署脚本不会自动执行这些恢复操作。

## 配置预览与验证范围

在本机也可以只生成预览，不安装软件、不连接数据库、不申请证书：

```bash
bash deploy.sh --dry-run \
  --domain shop.example.com --email ops@example.com \
  --output-dir /tmp/wybo-deploy-preview

bash -n deploy.sh deploy/backup.sh
python3 -m unittest discover -s deploy/tests -v
```

预览目录含随机样例凭据，请勿公开。验证覆盖凭据稳定性、输入注入、文件权限、代理 / SSL 配置、数据库监听限制、工具链版本选择及完整预览流程。开发机是 macOS，尚未在真实 Linux 公网服务器申请证书或完成端到端安装；首次实机部署仍需核对安装结果。

支付配置见 [支付渠道配置指南](支付渠道配置指南.md)。

## 启用代理分站

已有站点可使用 `update --station-root example.com --cf-dns-credentials /root/wybo-cloudflare.ini` 启用泛域名店铺，使用 Cloudflare DNS 验证申请证书并自动续期。现有凭据保持不变。准备 DNS、Token 权限、配置文件和开通流程见 [代理分站](代理分站.md)。
