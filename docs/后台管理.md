# Wybo 后台管理

当前本地入口：[http://127.0.0.1:5175/admin](http://127.0.0.1:5175/admin)。首次初始化默认账号 `admin` / `admin123`；已有数据库沿用原账号。实际账号密码、后台路径、2FA 由店主管理。

## 已实现页面

- 经营概览：7 / 30 / 90 天收入、商品成本、销售利润、成交数、每天 PV / UV、库存待办、商品排名、CSV 报表。
- 商品与定价：商品新增、编辑和删除，分类新增和删除，图片上传、自动 / 手工发货方式、采购成本和售价、即时利润预览、上下架。售价 0 表示待定价，不可下单。
- 订单管理：真实订单、状态筛选、分页、详情、已发卡密、待发货订单补发。
- 卡密库存：按商品和状态筛选、分页、默认隐藏内容、批量导入、重复检测、可售卡停用、本页多选与批量删除。
- 分销代理：代理资料、启停、商品专属售价、专属链接 `/?agent=CODE`、成交数及金额。
- 支付渠道：Stripe、易支付、DujiaoPay、BEpusdt 的服务端下单和回调验签。
- 站点设置：网站名称、Logo / 浏览器图标、文案、默认兑换地址；下单防护、邮件与推送、支付地址分标签管理。
- 邮件与推送：位于站点设置标签页；Bark 手机成交通知、Resend 发货邮件、店主成交邮件、HMAC Webhook、持久化发送队列、失败自动重试和手动重试。
- 安全设置：自定义后台入口、修改密码、验证器 TOTP 两步登录、旧会话撤销。

优惠券和多条公告保留原有管理 API；本次后台通过站点设置编辑首页公告。暂未接入支付渠道的自动退款；原有退款接口仅标记本地退款状态，实际退钱必须在支付商户侧完成，界面未提供误导性的“一键原路退款”。

## 售后语音播报

有售后工单权限的管理员可在后台顶栏点击「售后播报」，选择「开启播报」，也可先点击「试听播报」检查声音。开启后每 15 秒检查新工单和顾客追问，播报“您有 N 条新的售后消息，请及时处理”，同时显示文字提醒，并刷新当前打开的工单列表及详情。商家回复、内部备注和开启前的历史消息不会触发播报。

播报在后台各页面持续运行，只朗读新消息数量，不朗读主题、联系方式或工单正文。点击「关闭播报」会停止检查和当前声音。开关偏好按本浏览器的管理员账号保存；刷新、重新打开后台或重新登录后，需要再次点击「开启播报」以启用浏览器声音。请保持后台页面打开，并确保设备音量和浏览器声音权限可用；浏览器不支持语音或播放失败时会显示提示，后台标签页受浏览器节能策略影响可能延迟。

## 卡密批量删除

在「卡密库存」勾选卡密，或用表头复选框全选本页可删除卡密，再点击「批量删除」并核对数量确认。未关联订单的可售或已停用卡密都可以删除；已预占、已售出、已替换、售后退款或关联订单的卡密不能勾选。翻页、切换商品或状态筛选会清空选择。

删除后无法在后台恢复，相关商品的可售库存会重新计算；删除已停用卡密不会减少剩余可售卡密数量。若所选卡密不存在、变为不可删除状态或库存更新失败，整批删除会取消，不会只删除一部分。操作沿用库存管理权限。

## 网站品牌与下单防护

「站点设置 → 基本信息」可修改网站名称、品牌短名称、上传 Logo / 浏览器图标、修改公告、客服和默认兑换入口。「下单防护」由店主填写正式地址及 Cloudflare Turnstile 的 Site Key / Secret Key，默认关闭；开启后网页与直接调用 API 均须通过服务端验证后才能创建订单。详细操作、域名要求与排查见 [站点设置与人机验证](站点设置与人机验证.md)。

## 支付方式展示

在「支付渠道 → 配置渠道 → 前台展示」编辑对外名称、上传 Logo 并预览。保存后订单支付与购买弹窗同时生效；留空名称或恢复默认 Logo 会使用系统默认。DujiaoPay 和 BEpusdt 默认对外显示「USDT支付」，收款网络仍须按商户实际配置设置。Logo 支持 PNG / JPG / GIF，最大 2 MB。

## 商品图片、删除与发货方式

「商品与定价 → 新增 / 编辑商品」直接上传商品图片，支持 PNG / JPG / GIF，最大 2 MB、最大 4096 × 4096。上传后先预览，保存商品后生效；可恢复品牌默认图片。原有图片链接可以保留，新图片通过上传替换，不再需要填写链接。

商品行提供「删除」，「商品分类」弹窗也提供分类删除。均须确认后才执行；分类下仍有商品时，先调整商品归属。有订单、卡密、库存批次、采购或代理价格记录的商品不能删除，改用下架保留历史数据。未使用的商品和空分类可直接删除，后台不提供恢复入口。

每件商品可选择：

- **自动发货**：先导入卡密，按可售库存下单并预占；付款成功后自动发卡。库存异常的待发货订单，可补货自动补发，或在「订单管理 → 发货处理」确认库存补发。
- **手工发货**：无需预存卡密，商品上架且售价大于 0 即可购买，单次最多 99 份。付款成功后保持待发货，自动补发任务和补货都不会替它发货。进入「订单管理 → 发货处理」，按购买数量填写内容，每份一行；账号密码可写为 `账号----密码`，内容与密码各不超过 255 字节。核对并勾选确认后发送，订单完成。顾客凭订单号和联系方式领取内容，启用 Resend 后会进入发货邮件队列。

发货方式和成本均在下单时保存快照；后续修改商品不改变旧订单的发货方式。手工订单不消耗卡密库存，不计入低库存预警；前台明确提示等待店主处理。发货接口校验付款状态、份数及重复内容，重复提交不会重复发货；发货内容沿用卡密的访问权限、脱敏和售后机制。

更新部署后新增字段会自动迁移，旧商品、旧订单默认保持自动发货。未在真实商户环境发起付款，本次流程验证使用隔离数据库和模拟支付状态。

## 商品兑换与订单查询

在「商品与定价 → 编辑商品」填写「兑换地址」和「兑换说明」。地址填写实际兑换平台的 HTTP(S) 链接，说明写清账号要求和操作步骤，不按商品品牌猜测入口。支付成功并发卡后，用户查询订单即可复制卡密、点击「前往兑换」，Resend 发货邮件也会附上入口和说明。旧订单与下架商品同样读取对应商品当前的兑换配置；修改地址后无需重发卡密。未填写商品兑换地址时，使用「站点设置 → 基本信息 → 默认兑换地址」，默认已设为 https://cdk.fksanta.cc/。可在后台更换或清空默认地址；商品单独填写的地址优先。两处均为空时提示用户通过订单售后联系店主。

订单查询结果与查询表单分开显示；查到订单后表单和最近订单自动折叠，订单编号、时间和售后也可按需展开。待支付与待发货状态每 6 秒向服务端核对一次，后台标签页暂停查询，只有服务端确认发货后才展示卡密与兑换入口。

## 利润口径

金额以整数分入库，界面显示人民币。销售利润 = 订单实收 − 下单时的采购成本总额。例如 1 份成本 ¥105、售价 ¥115，成交后销售利润为 ¥10；2 份则为 ¥20。优惠券和代理售价影响实际收入。

成本在下单时保存快照。修改商品成本不影响历史订单。历史订单缺少成本时不假设成本为 0；仪表盘提醒未纳入利润的订单数。只按 `paid_at` 统计 paid / completed，排除待付款、关闭及已退款订单。这里未扣除通道手续费、税费、代理佣金等额外支出。

流量从页面真正访问后开始记录，不补造历史数据。统计首页、订单查询、购买指南；不统计后台/API。每日按访客 IP + UA 的 HMAC 匿名指纹去重，不存原始 IP/UA，跨日 UV 累加。统计日以 Asia/Shanghai 为准。默认不信任代理请求头；反向代理部署时按下面的可信代理配置获得真实 IP。

## 支付配置

先在“站点设置 → 支付地址”填写：

- 公网回调基础地址：`https://你的域名/api/v1/pay/notify`
- 付款返回地址：`https://你的域名/orders`

完整回调地址分别为基础地址后加 `/stripe`、`/epay`、`/dujiaopay`、`/bepusdt`。本地 localhost 无法接收外部支付回调。

| 渠道 | 必填项 | 补充 |
|---|---|---|
| Stripe | Secret Key、Webhook Secret | CNY 一次性付款；支持跟随 Stripe 后台动态展示，或手动选择银行卡 / 支付宝 / 微信；须先在 Stripe 开通对应方式 |
| 易支付 | 网关地址、PID、商户密钥 | 标准 submit.php MD5 协议，type 常用 alipay / wxpay |
| DujiaoPay | API URL、Key ID、API Secret、独立 Webhook Secret | 默认 https://www.dujiaopay.com；chain / token_id 可同时省略 |
| BEpusdt | 自部署网关地址、API Token | 默认 usdt.trc20；amount 为 CNY 法币金额，actual_amount 为链上币量 |

参考：[DujiaoPay 文档](https://www.dujiaopay.com/docs)、[BEpusdt 文档](https://github.com/v03413/BEpusdt/blob/main/docs/api/api.md)。BEpusdt 文档未提供查询 API，本实现不虚构补单查询接口。

渠道仅在完整配置并启用后出现在前台。验签、币种、商户信息和订单金额通过后才发卡，重复回调不会重复发货。停止渠道只禁止新付款，原有配置仍可验证在途订单回调。已关闭订单若收到真实有效的到账回调，仍记入收入并发货；缺库存则保留 paid，等待补货后手动补发。

目前只做本地协议和模拟回调验证；商户密钥配置后仍应使用各平台沙箱或测试小额交易验收。

## Bark、Resend 和成交推送

### Bark 手机通知

在「站点设置 → 邮件与推送 → 成交订单推送」配置，无需启用 Resend：

1. 在 iPhone 安装并打开 [Bark](https://bark.day.app/)，允许通知，找到设备 Key。若 App 显示 `https://api.day.app/YourKey/测试内容`，设备 Key 是 `YourKey`，不要填写整条链接。
2. Bark 服务器地址留空使用 `https://api.day.app`。自建服务填写对应根地址，也可填写其 `/push` 接口地址；不要包含设备 Key、查询参数或消息正文。
3. 填写设备 Key；消息分组可留空，默认为「Wybo 成交订单」。Key 加密存储，读取时显示 `********`，留空或保留星号沿用已有值；关闭 Bark 开关即可停用。
4. 打开「启用成交推送」与「启用 Bark 通知」，点击页面底部「保存邮件与推送」。
5. 点击「发送 Bark 测试通知」，在手机确认收到。测试使用已保存配置，不包含真实订单，也不会创建成交记录；即使尚未启用自动推送，也可单独测试已保存的 Key。

新付款订单将进入持久化队列，推送商品名称与数量、订单号、实收、订单快照成本、销售利润、渠道、发货状态与成交时间；分站订单标明来源分站。销售利润为实收减商品成本，未扣手续费、佣金等；未知成本会显示「待补全」。通知不包含卡密或买家联系方式，自动发货、手工发货订单均支持，手工订单付款后即可通知，无需等待人工交付。

「推送记录」中的渠道显示「Bark 成交通知」，可查看结果并重试失败任务。支付回调重复处理不会新增同一订单的 Bark 通知。队列采用至少一次送达，网络超时后重试可能造成手机重复收到；Bark 返回 HTTP 成功且 JSON `code=200` 才记录发送成功，这代表服务接受请求，手机接收仍取决于 APNs、网络与系统通知设置。测试操作另记入审计日志。

协议参考：[Bark REST API](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md)。请求为 `POST /push`，设备 Key 和消息使用 JSON 请求体传输，生产环境使用 HTTPS。

### Resend 邮件与 Webhook

1. 在 Resend 验证发件域名，获取 API Key，进入「站点设置 → 邮件与推送」。
2. 填写 API Key 与发件人，例如 `望月小铺 <orders@example.com>`，启用邮件通知。
3. 启用成交推送，填写店主接收邮箱，或填写 Webhook URL 和签名密钥，可与 Bark 同时使用。

顾客发货邮件包含本订单卡密。店主通知包含订单实收、成本与利润（有成本时）；Webhook 不包含买家联系方式或卡密。

Webhook 请求体 JSON 包含 `event`、`event_id`、`order_no`、`total_cents`、`cost_cents`、`pay_method`、`status`、`paid_at`。签名 `X-Wybo-Signature = hex(HMAC-SHA256(推送密钥, 原始请求体))`。接收端应验证签名，并按 event_id 去重；队列按至少一次送达处理，网络不确定性可能重发。

队列每 10 秒检查，失败指数退避、最多尝试 5 次。“推送记录”显示最近 100 条，可重试最终失败记录。禁用相关配置后，未发送任务取消。

## 登录、安全和恢复

后台路径支持单层 3–64 位字母/数字/短横线/下划线，例如 `/moon-console`，系统保留路径不可使用。更改路径后记下新地址。固定 API 前缀仍为 `/api/v1/admin`，请求必须附带匹配的 `X-Admin-Path` 和登录 token；更改入口不能替代登录保护。

密码修改需要当前密码，已启用 2FA 时还需验证码。新密码 12–72 字节。2FA 使用 RFC6238 SHA1 / 6 位 / 30 秒，支持验证器扫码或手动输入密钥。绑定待确认密钥 10 分钟失效。登录时拒绝已使用验证码；改密码、启用或停用 2FA 会撤销原登录。

丢失验证器或忘记入口/密码时，具有服务器文件访问权限的管理员可执行本地工具（不暴露 HTTP 接口）：

```bash
cd backend
# 只恢复已知后台路径
 go run ./cmd/admin-recover --username admin --admin-path /moon-console
# 仅停用丢失的验证器
 go run ./cmd/admin-recover --username admin --reset-2fa
# 安全读取新密码后通过 stdin 传给工具，不写到参数或历史记录
 read -s 'wybo_recovery_password?新密码: '
 printf '%s\n' "$wybo_recovery_password" | go run ./cmd/admin-recover --username admin --password-stdin
 unset wybo_recovery_password
```

工具沿用当前 DB_DSN 配置，所有恢复操作都会撤销现有会话。本次未更改真实管理员密码或启用 2FA。

## 部署配置

完整原生安装脚本及 PostgreSQL / SSL / systemd 配置见 [原生部署](原生部署.md)。四个渠道的字段、Webhook、沙箱及真实付款验收见 [支付渠道配置指南](支付渠道配置指南.md)。脚本使用随机初始密码，不沿用本地开发的 `admin123`；2FA 由用户在安全页面自行开启。

设置稳定、随机且至少 32 字节的 `JWT_SECRET`；release 模式会拒绝过短密钥。该密钥也用于加密支付密钥、Resend Key 和 TOTP 秘钥，必须与数据库一起妥善备份；已有加密配置后不能直接轮换，否则无法解密旧配置。`ADMIN_PASSWORD` 只影响首次初始化，已有账号请在安全页面改密。

默认 `server.trusted_proxies` 为空。Nginx 在本机时可在 `configs/config.yaml` 配置明确的反代 IP，例如：

```yaml
server:
  trusted_proxies: ["127.0.0.1", "::1"]
```

只填写实际反代地址，避免把访客直接传入的 X-Forwarded-For 当真。Nginx 配置 `try_files $uri $uri/ /index.html` 以支持自定义后台路径；`/api/` 和 `/uploads/` 转发后端。正式环境使用 HTTPS。

SQLite 备份使用 SQLite backup API，或停服后复制；不要直接复制正在写入的 SQLite 文件。本次升级前备份在 `backend/data/backups/`，默认不通过网站对外暴露。
